# Master Execution Roadmap

## Phase 1 — Current

Deliver the complete Personal/Student public presence:

- approved Public Website;
- dedicated owner-approved Public Website CMS;
- published-content/backend/media/inquiry/analytics contracts;
- Cloudflare deployment readiness;
- integrated security, QA and release evidence.

Exit requires FE-02, FE-03, P1-SEC-01, P1-QA-01 and P1-REL-01 complete, followed by explicit owner deployment/release authority.

## Phase 2 — Admin & Operations Dashboard

Build staff identity/permission foundation first, then leads/clients/websites/projects/services/billing/support/content orchestration/security/operations modules. Use the existing Admin blueprint and security baseline. Do not collapse the dedicated Public CMS.

## Phase 3 — Personal Client Panel

Build customer identity/security, multi-website portfolio, project/onboarding/approval flows, services/renewals/support/billing, Root Health and secure Open Website Admin SSO. Normal website content remains in website CMS.

## Phase 4 — Reusable Client Website CMS

Extract/refactor the generic professional CMS core from the approved Public CMS while preserving secure site isolation and profile-driven supported capabilities. Produce a reusable CMS template, local developer harness, security baseline, validation suite and deployment template.

## Phase 5 — Client Public Website Factory

Create a reusable public website runtime/template architecture and major prompt system that takes an approved Website Blueprint/site brief and generates a client-specific site profile + website using supported modules. Connect it to that client’s CMS. Every generated site must pass the same release gates.

## Cross-phase rule

Do not create hidden technical debt by implementing later-product requirements inside the wrong current application. Prefer explicit contracts and reusable packages only when ownership and security boundaries remain clear.
