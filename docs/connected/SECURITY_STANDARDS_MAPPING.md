# Security verification scope and standards mapping

The 151 owner vulnerability titles are copied verbatim from the mandatory baseline into SECURITY_OWNER_TITLES.csv. The official tagged ASVS5.0.0 CSV (SHA256 98c8fe911b9edb403af8ee05d3ce8201ecac2659e313b053890a62847cdcf680, CC BY-SA4.0) supplies all 345 requirement IDs/texts/levels in ASVS_5_0_0_MATRIX.csv. Attribution: OWASP Application Security Verification Standard project, https://github.com/OWASP/ASVS/tree/v5.0.0. These matrices explicitly record related local evidence and remaining gates; they do not claim ASVS certification, complete L2/L3 coverage or independent acceptance.

OWASP Top10:2025 mapping: A01 access control → CMS current actor/scopes and published reader; A02 security misconfiguration → strict entries/bindings/headers; A03 supply chain → exact locks/toolchain/SBOM/audit; A04 cryptographic failures → signed contexts, token hashing and managed keys gate; A05 injection → prepared SQL/context sanitization; A06 insecure design → threat model/immutable states; A07 authentication → Access JWT/current sessions and real MFA gate; A08 integrity → exact source/revisions/CAS; A09 logging/alerting → audit/minimized rejection logs and alert operations gate; A10 exceptional conditions → explicit failure/compensation/503 and bounded services. Official repository source snapshot is indexed in the outer evidence.

OWASP API Top10:2023: API1/3/5 → object/property/function permission gates and public projection; API2 → strict identity/session/current grants; API4/6 → bounds, service rate limits and intake workflow/retry constraints; API7 → fixed provider destinations/no arbitrary URL import; API8 → strict production entries; API9 → exact public/CMS endpoint boundaries; API10 → bounded fixed-provider/scanner contracts. Real provider/edge/load behavior remains open.

NIST SP800-218 SSDF1.1 remains the final baseline (no draft substituted): PO → frozen authority/threat model/roles/phase gates; PS → immutable hashes/access separation/secret boundaries; PW → code review, dependency pins, typed checks, negative/browser/media/authorization/race tests and reproducible build; RV → dated advisory results, recorded risks, incident/patch/recovery workflow requiring operational acceptance. Security testing performed by the implementation author is self-validation, not an HQ or independent security decision.

Current Cloudflare documentation was retrieved read-only from the official cloudflare/cloudflare-docs production repository for Access JWT validation, Worker bindings, D1 API and private/public R2 behavior. Direct developer-doc hosts were denied by this environment's network policy; successful official-source snapshots, URLs, hashes and failed attempts are preserved in evidence/official-references/index.json. Local Wrangler identity is checked read-only; actual account/policies/bindings remain unverified until explicit environment/action authority.

Integrated P1-SEC-01 status: BLOCKED for release. Dedicated local adversarial gates are included, but provider MFA/configuration, retention/deletion, alerting/backup/recovery, full applicable ASVS evidence and independent review remain required. No risk acceptance is invented and no applicable requirement is marked complete merely from a test count.
